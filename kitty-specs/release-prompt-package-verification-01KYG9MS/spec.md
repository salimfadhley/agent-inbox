# Spec - Release prompt package verification

## What this is

Agents bootstrap from the served prompt. If that prompt tells them to install a package
version that the package index cannot resolve yet, onboarding fails before the agent has
enough context to diagnose whether mail is actually broken.

This mission adds a release gate that verifies the prompt, package index, local tool, and
hub version agree before the live prompt advertises a version.

## Problem

The onboarding prompt intentionally tells every new agent to run a concrete install
command, for example:

```bash
uv tool install --refresh --no-cache --force "agent-inbox[clients]>=X.Y.Z"
```

That is useful only if `X.Y.Z` is available to the resolver. A mismatch between the hub's
served prompt and the published package creates a hard first-step failure:

- the agent follows the prompt exactly;
- `uv` cannot resolve the advertised version;
- the agent may conclude its mailbox setup is broken even though an older compatible tool
  might work.

## User scenarios

1. **Release succeeds.** A release publishes the package, verifies a clean install from the
   public index, then deploys a hub whose prompt advertises that same version.
2. **Package not visible yet.** The package has been built but the resolver cannot see it.
   The release gate fails before the prompt is updated or the deployment is considered
   complete.
3. **Prompt drift.** A developer changes prompt text manually to a version that does not
   match the package/hub version. CI or release verification fails.
4. **Agent bootstrap.** A fresh agent follows the served prompt and the install command
   resolves on the first attempt.

## Functional requirements

| ID | Requirement | Status |
|---|---|---|
| FR-001 | Provide a release verification command or script that extracts the version advertised by the served prompt and verifies it against the package version intended for release. | proposed |
| FR-002 | The verification performs a clean resolver check equivalent to the prompt's `uv tool install --refresh --no-cache --force "agent-inbox[clients]>=<version>"`. | proposed |
| FR-003 | The release process fails if the advertised prompt version cannot be resolved from the configured package index. | proposed |
| FR-004 | The hub descriptor, package version, and prompt minimum version are compared and any mismatch is reported with a concrete fix. | proposed |
| FR-005 | The prompt text is generated from one canonical version source where practical, rather than hand-copying a literal into several files. | proposed |
| FR-006 | A release note or deployment log records the verified version and the command that was checked. | proposed |
| FR-007 | If the package index is temporarily unavailable, the release gate fails loudly rather than silently publishing a prompt that agents cannot follow. | proposed |

## Non-functional requirements

| ID | Requirement | Threshold | Status |
|---|---|---|---|
| NFR-001 | Verification catches real resolver failures. | The check runs in a clean environment or otherwise avoids reusing the already-installed local checkout. | proposed |
| NFR-002 | The check is safe for CI and release automation. | It prints no tokens or local deployment secrets and is deterministic except for package-index availability. | proposed |
| NFR-003 | Failure is actionable. | Error output names the version, the failing command, and whether the failure is prompt drift, package unavailability, or hub mismatch. | proposed |

## Constraints

| ID | Constraint | Status |
|---|---|---|
| C-001 | Do not put deployment-specific hostnames or tokens into committed tests or docs. | accepted |
| C-002 | The live prompt remains generated by the running mailbox version; agents must not depend on stale copied instructions. | accepted |
| C-003 | The release gate must not require a human to inspect the package index manually. | accepted |

## Success criteria

| ID | Outcome |
|---|---|
| SC-001 | A release cannot complete if the prompt advertises a version that `uv` cannot resolve. |
| SC-002 | A fresh machine can run the exact install command from the prompt and get the advertised tool version. |
| SC-003 | The hub reports the same version family that the prompt and package advertise. |
| SC-004 | A test or CI check fails if prompt text is manually edited to a nonexistent version. |

## Out of scope

- Changing the package repository or distribution name.
- Supporting offline installation.
- Replacing `uv` as the documented installer.
