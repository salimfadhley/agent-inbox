# agent-inbox 1.7.0

Generated hook commands now invoke the package through an isolated `uv run`
environment. Installation records uv's absolute path, so a GUI session need not
inherit the installer's PATH. All supported harness adapters share this launcher;
mail-checking and waiting behavior stays in the package.

## Existing installations

Upgrade the client, then run `agent-inbox install-hook --engine <harness>` in each
project whose hooks you want to migrate. Saved commands do not change just because
the package was upgraded. Other tools' hooks are preserved.

**Codex users must re-trust the changed entries in `/hooks` after this one-time
migration.** Repeating an unchanged installation produces identical hook text.
The hook's Python and package compatibility floors are explicit constants;
changing either, or moving uv, requires another announced migration and re-trust.
An intentional Python-floor migration must accompany future interpreter upgrades.

Codex uses short checks at session start, prompt submission and turn completion.
It cannot wake a fully idle session without a blocking Stop waiter, so none is
installed, even with `--rewake`.

`doctor` now warns about the obsolete held Codex waiter and Windows executable
paths saved with POSIX single quotes. It provides regeneration and re-trust steps
without modifying trusted commands. Presence, known command defects and human
trust are reported separately; presence is not proof of lifecycle activation.

## Package updates and operational limits

Package updates need no hook rewrite. uv's cache determines when a new package is
resolved; the existing client-version notice now includes a command to refresh
the same package requirement used by hooks. A current MCP server does not prove a
separately cached hook package is current.

uv must be available when installing hooks. A cold cache needs network access;
resolver failures occur before the package's fail-silent hook code starts. A warm
offline cache can be used with uv's offline mode; a stale cache with unavailable
network may still attempt revalidation.

The module invocation avoids keeping `agent-inbox.exe` open on Windows, the cause
of previous upgrade failures. uv remains the child process's parent, however.
Long-lived waiters may keep `uv.exe` open and prevent `uv self update`; this residual
Windows risk has not been tested natively. Stop waiters before updating uv itself.
