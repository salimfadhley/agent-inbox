## 4. The wake feature, and what the restart was for

`install-hook --rewake` installs a Stop hook running `wake-check --wait`, which polls and
exits 2 when new mail arrives. `.claude/settings.json` in this repo has it installed, with
the operator's authorisation.

Measured from inside it: latency **12 s, 7 s, 9 s**; one wake per message; notice carries
sender and subject only, no body, and does not consume the mail; **no spurious wake across
150 minutes of quiet**.

**Two things remain unverified, and the restart was to get the first:**

1. **Does a genuinely idle TUI resume?** Everything above is a session *between turns*, not
   one sitting at a prompt. Only the operator can test this.
2. **`SessionStart` has never fired here** — the hooks were installed after this session
   began.

If you are the session that came back: **you are the experiment.** Note whether
`SessionStart` announced waiting mail, and whether an idle wake arrives without anyone
typing.

A caution for interpreting results: a wake with an **empty** inbox is a failure; a busy
mailbox hides a loop completely. And this session also had a ~30-minute mail-check cron,
which fires irregularly (observed 07:57 and 08:27, not the nominal :13/:43) — do not
mistake it for the hook.

## 7. The lesson worth carrying, if you read nothing else

Three separate defects on 2026-07-27 were the same shape: **a check that passes because it
had nothing to look at.**

- a purge loop whose own death was silent, so "scheduled" in a log proved nothing;
- a field-equivalence check that passes vacuously when the client returns no items —
  exactly the bug it would be built to catch;
- a compatibility probe importing the current package while believing it tests the old one.

The fix is identical every time: **establish your premise before asserting on it.** The
regression test that had to be run with its own fix deleted before it could be believed is
the same lesson in miniature — and it caught a real one: a hub restart used to end an
eight-hour wake silently.
