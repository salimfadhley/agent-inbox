## 1. What this project is

**agent-mailbox** — a SQLite-backed mailbox that lets local LLM agents message each other,
so a human no longer has to relay prompts between them. Repo:
`github.com/salimfadhley/agent-inbox`; the installable package is `agent-mailbox`. One
lightweight container: a Litestar + msgspec HTTP hub over SQLite (aiosqlite), a stdlib-only
client + an `mcp[cli]` MCP client, and a server-rendered human console. On the wire it speaks
**ActivityStreams / ActivityPub** (`inbox`/`outbox`/`objects`).

**It's a free-software vanity project** — nobody makes money whether people use it or not. The
intended public stance is "try all of these, they're all open source."

### Positioning (the differentiation analysis — see §4, a decision is pending)

One-line positioning candidate, **not yet confirmed by the owner**:

> **agent-mailbox is the inter-agent mailbox you can actually host on the open internet** —
> standards-based (ActivityStreams/ActivityPub, built to federate), with real auth (per-human
> 2FA, per-device tokens) and a visual console for human oversight, kept deliberately to
> *messaging only*, in one small SQLite container.

The three things no competitor in the survey does: (1) a **federation-standard wire format**;
(2) **real authentication** (so it's the only one safe to expose externally); (3) **visual
human oversight** via the console's interactive flow graph. Plus **non-blocking out-of-band
wake** (the v0.12.3 hook) which fixes postal-mcp's known "agent won't return to the mailbox"
failure. Differentiation-by-subtraction: deliberately *no* file leases / build slots /
semantic search — that restraint keeps the surface small enough for an LLM and small enough to
federate. Full survey: `docs/research/competitive-survey-findings.md` (mission 0029).

## 2. What has shipped

- **Full console UI** — dashboard, agents, mailbox browser, threads, compose, prompts page
  (one prompt; agent/host/admin depends on config), and a vendored client-side **flow graph**
  under a real CSP.
- **8080 takeover** — the new stack replaced the old service on examplehub, preserving the old data
  volume (`agent-mailbox_agent-mailbox-data`; project name `-p agent-mailbox` is load-bearing).
- **Automated CI/CD** — GitHub Actions: CI (check + test matrix + smoke + build) gates
  `docker.yml` via `workflow_run`. Push to `main` → `:edge`; a `v*` tag → `:X.Y.Z` + `:latest`
  + `:X.Y`, multi-arch amd64+arm64. Live smoke tests run the real Docker image as a sidecar.
- **Authentication (v0.12.x)** — Argon2id passwords, TOTP (pyotp) + inline-SVG QR, Fernet-
  encrypted TOTP secrets, SHA-256 device tokens, per-source login throttle, Jenkins-style
  bootstrap admin (random password printed once to the boot log). Three-mode `AUTH_MODE`
  (`off` | `warn` | `enforce`). Currently deployed on examplehub in **warn** mode. All users are
  admins (no differential security, by decision). ADR 0010.
- **Wake / live-session push (v0.12.3, mission 0017)** — a client-side Claude Code hook so an
  agent notices new mail the moment it's next active. `wake-check` / `install-hook` /
  `uninstall-hook` CLI. Pure `wake_response()` + a fail-silent I/O wrapper; announce-once
  watermark; only sender+subject emitted, never a body. Hub untouched (ADR 0011); a structural
  test forbids the hub/engine from ever naming a hook/wake/harness. Channels deferred (gated
  preview).

## 5. Ground rules (do not skip)

- **Four gates must stay green:** `uv run pytest`, `uv run ruff check`, `uv run ruff format
  --check`, `uvx pyright@1.1.411 src`. Ruff line length is 88 chars and it counts characters
  (an em-dash is 1) — it won't reflow docstrings/comments, so hand-wrap those.
- **Charter:** no deployment-specific hostnames, IPs, secrets, or organisation names in code,
  docs, or tests. Deployment specifics (examplehub, Portainer, Docker Hub creds) live only in the
  gitignored `.claude/CLAUDE.md` and the owner's private memory — never in the tracked repo.
- **Workflow:** spec-kitty missions land on a feature branch off `main`, PR-bound to `main`.
  Don't handle passwords/tokens in plaintext; the owner sets GitHub secrets themselves.
- **Console quirk:** Litestar can't serve GET and POST on the *same* path (GET 500s) — use
  distinct paths (`/login` GET, `/login/submit` POST, etc.).
- **Commit trailers** used on this project:
  `Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>` and a
  `Claude-Session:` line. Commit/push only when asked; branch first if on `main`.
- **Inter-agent mail:** at session start, check the agent-inbox hub (`ping`, `check_inbox`) if
  the MCP tools are present; the admin address for this project is `agent-inbox/admin`.
